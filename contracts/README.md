# Контракты API

Общие артефакты между сервисами и клиентами.

- `openapi.yaml` — спецификация HTTP API (генерируется из сервиса core)
- `asyncapi.yaml` — события/очереди (когда появятся)

Правило: контракт — источник истины для фронтенда и других сервисов.
Меняется сначала здесь, потом в коде.

## Владельцы

| Артефакт | Кто меняет |
|---|---|
| `openapi.yaml` | бэкенд (источник), фронтенд (предложения через PR) |
| `asyncapi.yaml` | бэкенд |

Каталог в совместном владении: изменение не проходит без ревью обеих команд.

## Правила изменения

1. Схема генерируется из Laravel и коммитится сюда — руками не правится.
2. Обратная совместимость: удаление или переименование поля — major-версия.
3. Каждое изменение — запись в `CHANGELOG.md` и метка версии.
4. CI проверяет, что схема в репозитории совпадает с кодом сервиса.
5. Фронтенд генерирует типы и клиент из схемы, а не пишет их руками.

## Версионирование

- `v1`, `v2` — major-версии контракта, соответствуют префиксам `/api/v1`, `/api/v2`.
- Внутри версии — только обратно совместимые изменения.
- Deprecated-эндпоинт живёт до следующего major-релиза.

## Будущее разделение

`contracts/` — самодостаточный каталог: `git subtree split --prefix=contracts`
даст отдельный репозиторий с историей. После выноса контракт подключается
к потребителям как зависимость: npm-пакет для фронтенда, composer-пакет для PHP.
