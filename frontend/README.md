# Frontend

Папка зарезервирована под клиентское приложение (SPA).

## Текущее состояние

Пусто — фронтенд ещё не начат. Бэкенд (`services/core`) отдаёт чистый REST API,
поэтому фронтенд не влияет на его работу.

## Границы доступа

- Фронтенд-команде **не нужен** доступ к `services/core/` и `infra/`.
- Общий артефакт — `contracts/`: OpenAPI-схема и сгенерированный клиент.
- Пока проект живёт в монорепозитории, изоляция держится на правилах ревью
  (`CODEOWNERS`, защита `main`). После выноса папки в отдельный репозиторий
  (`git subtree split --prefix=frontend`) изоляция становится физической.
- Секреты бэкенда (`APP_KEY`, `DB_*`, SMTP, доступ к PostgreSQL и Redis)
  во фронтенд не передаются никогда.

## Планируемый стек

Уточняется. Базовые варианты:

| Вариант | Когда выбирать |
|---|---|
| React + TypeScript + Vite | самая широкая экосистема, много готовых UI-китов |
| Vue 3 + TypeScript + Vite | проще вход, хорош для админок |
| SvelteKit | минимум кода, быстрый рантайм |

## Договорённости

1. **Контракт, а не догадки.** Типы API берутся из `contracts/openapi.yaml`
   (генерация клиента), а не пишутся руками по памяти.
2. **Отдельное окружение.** Свои `package.json`, `node_modules`, `.env` —
   ничего общего с `services/core`. Docker-фрагмент появится как
   `frontend/compose.yml` и подключится в `infra/docker-compose.yml` через `include:`.
3. **Только HTTP-обмен.** Фронтенд не импортирует код бэкенда; авторизация —
   Bearer-токены Sanctum.
4. **Готовность к выносу.** Папка самодостаточна: `git subtree split --prefix=frontend`
   даст отдельный репозиторий с историей.
5. **Моки по умолчанию.** Пока эндпоинт не готов, фронт работает на MSW-моках,
   сгенерированных из OpenAPI, а не на устных договорённостях.
6. **Один origin.** Все запросы идут на один базовый URL (`VITE_API_URL`),
   CORS настраивается на стороне API.

## Переменные окружения

`frontend/.env` (не коммитится, шаблон — `.env.example`):

| Переменная | Назначение |
|---|---|
| `VITE_API_URL` | базовый URL API, например `http://localhost:8000/api/v1` |
| `VITE_MOCK` | `true` — включить MSW-моки вместо реального API |

## Запуск (когда появится код)

```powershell
cd frontend
npm install
npm run dev        # Vite dev-сервер
```

Порт `5173` уже зарезервирован в `infra/.env` (`VITE_PORT`).

## Работа без доступа к бэкенду

- `VITE_MOCK=true` + MSW-хендлеры, сгенерированные из `contracts/openapi.yaml`.
- Демо-аккаунты и тестовые токены выдаёт бэкенд-команда; реальные учётные
  данные БД фронтенду не нужны.
- Если нужен живой API — используется staging-URL, а не локальный запуск
  `services/core`.
