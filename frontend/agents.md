# II Web — правила для агентов

SPA-клиент к API `services/core`. Папка самодостаточна: после
`git subtree split --prefix=frontend` она становится отдельным репозиторием,
а этот файл — его корневым документом.

## 🚧 Границы доступа
- **Не читать и не менять** `services/core/` и `infra/` — этого кода у фронтенд-команды нет.
- Источник истины по API — `contracts/openapi.yaml`. Типы и клиент **генерируются**, а не пишутся руками.
- Секреты бэкенда (`APP_KEY`, `DB_*`, SMTP, доступ к PostgreSQL и Redis) во фронтенде отсутствуют.
- Прямых запросов в БД/Redis нет: только HTTP к API.

## 📦 Стек
Пока не выбран. Кандидаты: React, Vue 3 или Svelte + TypeScript + Vite.
После выбора стека раздел дополняется командами сборки, линта и тестов.

## ⚙️ Окружение
- `frontend/.env` — не коммитится, шаблон `.env.example`.
- `VITE_API_URL` — базовый URL API, например `http://localhost:8000/api/v1`.
- `VITE_MOCK` — `true` включает MSW-моки вместо реального API.
- Порт `5173` зарезервирован в `infra/.env` (`VITE_PORT`).

## 🔌 Работа с API
- Один базовый URL, версия в пути: `/api/v1/...`.
- Авторизация — Bearer-токен Sanctum; cookie-сессии не используются.
- Ошибки разбираются по единому формату из контракта, а не по тексту сообщения.
- Breaking changes приходят только с новой major-версией контракта.
- Пока эндпоинт не готов — MSW-хендлеры из OpenAPI, а не «договорились на словах».

## 🧪 Качество (когда появится код)
- TypeScript strict, ESLint + Prettier.
- Unit-тесты Vitest, e2e Playwright по мере роста.
- CI: генерация клиента из контракта + проверка, что сгенерированный код не разошёлся со схемой.

## 📝 Правила для агентов
- Не дублировать типы API вручную — только генерация из контракта.
- Не коммитить `.env`, `node_modules`, `dist`, `.vite`.
- Не создавать вложенные `.git` в подкаталогах.
- Локальный запуск: `npm install` → `npm run dev` (порт `5173`).
- Для живой проверки использовать staging-URL, а не локальный запуск `services/core`.
